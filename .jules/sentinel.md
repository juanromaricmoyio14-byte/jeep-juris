## 2023-10-27 - Prevent Object Prototype Pollution in Server Functions
**Vulnerability:** In `src/lib/consulter.functions.ts`, the `getLibraryDoc` server function used a permissive `z.string()` input validation for the `domain` parameter, which was subsequently used to index an object (`DOMAIN_DRIVE_KEYS[data.domain]`). This allows a potential object prototype pollution attack, enabling an attacker to access prototype properties like `__proto__`, `constructor`, or `toString`.
**Learning:** When user input is used to dynamically access object properties, specifically in server-side contexts, validating simply as a string is insufficient and can lead to prototype pollution, which might cause unexpected behavior or Denial of Service (DoS) crashes if the logic expects a specific type of value (like an array) but receives a function or object.
**Prevention:** Always use strict validation when using input to access object keys. Use `z.enum()` with explicitly defined allowed keys rather than a generic `z.string()` to enforce that the input strictly matches one of the expected valid keys.
