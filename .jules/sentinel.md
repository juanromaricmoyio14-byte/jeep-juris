## 2025-02-13 - Prevent Prototype Pollution / DoS with strict validation for object keys
**Vulnerability:** A server function endpoint (`getLibraryDoc`) accepted a raw string parameter (`domain`) which was then used to directly look up a value in a plain object (`DOMAIN_DRIVE_KEYS[data.domain]`).
**Learning:** If the user provided inputs like `"constructor"`, `"__proto__"`, or other special keys, it could crash the application or cause unexpected behaviour by looking up properties in the Object prototype rather than the intended specific keys. Even though standard prototype pollution often occurs on assignment, reading from user-controlled keys can result in a crash/DoS if it's not strictly typed or validated, particularly if the prototype method doesn't have the expected properties (e.g. `driveKeys.length` checks throwing if `driveKeys` becomes a function).
**Prevention:** Always validate user inputs strictly using enums (e.g., `z.enum([...])`) or mapping functions before using them to access object properties. Alternatively, use `Map` or a `null`-prototype object (`Object.create(null)`) for property mapping.
